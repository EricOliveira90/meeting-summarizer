### If REVISE, specific gaps:
- **Scope lock / Non-goals:** The scope cites "`PRD stories 12-18 and 37-50`," while the non-goals assign "`PRD stories 15-17 and 37-50`" outside this slice. The same stories therefore appear both inside and outside the scope lock. This violates boundary explicitness; cite only the stories this slice delivers and keep retry, recovery, cancellation, and operational stories exclusively out of scope.
- **In scope / canonical completion semantics:** The contract says a Job "finishes as `COMPLETED/TRANSCRIPT_READY`" after explicitly removing Summary work. `CONTEXT.md`, ADR-0001, and the PRD define a Job as complete only when both its Transcript and Summary exist. This violates the accepted completion boundary. Specify that `COMPLETED` is a server transcription-operation status rather than canonical Job completion, or use a status that does not declare the Job complete.
- **In scope / Test plan:** The contract promises, "The production graph uses one `FileManagerService` instance," but the matching sentinel-path test asserts only the path values received by consumers. Two production instances deriving or receiving the same paths would pass every planned assertion. This violates falsifiability; add an observable construction/identity assertion for the built production graph, or narrow the promise to one authoritative path interface.
- **In scope / Test plan:** The redaction case uses "a fake Whisper that writes `TRANSCRIPT_SENTINEL_TEXT` only to its requested output file" and then asserts that stdout, stderr, errors, and logs omit that text. Those channels never receive the sentinel, so an adapter that copies sensitive child output into an error can pass. This violates falsifiability. Make failure fixtures emit token and Transcript canaries through stdout/stderr and assert that captured errors and application logs redact or discard them.
- **In scope / Test plan:** The lifecycle promise requires completed steps "in order," but the matching test says only that "observable persisted steps/statuses follow the defined order," and the smoke observes only the final `COMPLETED/TRANSCRIPT_READY` state. An implementation that writes all intermediate states after processing, without exposing `EXTRACTING_AUDIO` or `TRANSCRIBING` while active, can pass. This violates UAT-verifiability; gate the extractor and transcriber and assert each intermediate state through authenticated status requests before releasing the next operation.
- **Existing behavior to preserve / Test plan:** The contract promises "health/CORS" and "Concurrency-one queueing," while the preservation entry only reruns "existing authenticated upload, list/detail, retry, delete, recovery, and Transcript-not-ready cases." The current suite has no assertion for CORS and no two-Job assertion that processing never overlaps, so either behavior can regress while all planned commands exit zero. This violates falsifiability; add an authenticated Origin/CORS assertion and a controlled two-Job concurrency test.
