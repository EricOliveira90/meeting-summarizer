### If REVISE, specific gaps:
- **In scope / Test plan:** The contract promises, "with neither credential exposed," but the matching test says only that requests return "their exact redacted auth errors." Exact response bodies do not fail if either sentinel credential is written to `console`, Fastify logs, stdout, or stderr. This violates falsifiability and UAT-verifiability, as well as the repository convention to keep secrets out of logs. Capture the relevant diagnostic channels and assert that neither the configured nor submitted sentinel credential appears.
- **In scope / Test plan:** The accepted timestamp is specified only as "`x-recorded-at` is ISO-8601," while the test plan says only to check "UTC time." This does not determine whether valid ISO-8601 forms without an offset, date-only values, week/ordinal dates, or leap seconds are accepted, and zone-less normalization can vary with the machine timezone. This violates falsifiability. Define the exact accepted timestamp grammar and add concrete accepted offset/UTC and rejected ambiguous/malformed cases.
- **In scope / Test plan:** The contract promises that Recording "size is 1 byte through 500 MiB inclusive," but the valid test matrix covers only "media/language/template/speaker matrices"; the invalid table checks only an over-limit Recording. An implementation that rejects exactly 500 MiB can therefore satisfy the stated tests. This violates falsifiability and UAT-verifiability. Add explicit HTTP boundary cases proving that 1 byte and exactly 500 MiB succeed and 500 MiB plus 1 byte fails on both aliases.
- **In scope / Test plan:** Invalid multipart requests promise "zero artifact, store, or queue effects," and the test requires "artifact/path, store, and queue spies [to] remain untouched" even for an empty or over-500-MiB stream. File size is known only after the stream is consumed; keeping the artifact collaborator untouched forces the handler to buffer up to 500 MiB or to bypass the declared artifact boundary. This violates single-session feasibility and leaves cleanup untestable. Permit a staged artifact write for stream validation, then require deletion and zero committed artifact/store/queue effects, with spies proving cleanup.
- **In scope / Test plan:** The Transcript route defines outcomes only when the Job is "absent, not `COMPLETED/DONE`, or ready with an artifact," and the test likewise covers only "absent, pending, and completed Jobs" with an artifact. A `COMPLETED/DONE` Job whose replaceable artifact collaborator returns `null` or fails has no specified status/body, even though the current artifact API explicitly returns `null` for a missing file. This violates boundary explicitness and falsifiability. Define and test the exact wire outcome for a completed Job with a missing or unreadable Transcript artifact.
